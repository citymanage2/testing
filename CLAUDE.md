# СМ Смета — навигация по проекту

Этот документ — карта проекта. Читай его в начале каждой сессии, чтобы понимать, где что лежит и как с этим работать.

## Что это за проект

СМ Смета — внутренняя система управления строительной компанией (коммерческое и промышленное строительство).
Заменяет разрозненные инструменты (Gectaro, Битрикс 24, Excel) единой платформой: сметы с ИИ-помощником, управление проектами, контроль бюджета, учёт материалов и П&У по каждому объекту.

Подробности — в .business/INDEX.md.

## Ключевые принципы проекта

1. **Достоверность важнее скорости** — ИИ ссылается на конкретные источники цен (прайсы, ФСНБ, собственная база), никаких цифр "из воздуха".
2. **Надёжность — основа доверия** — один необъяснимый сбой = откат команды к Excel. Стабильность не обсуждается.
3. **Всё в одном месте** — смета, проект, бюджет, ГПР, материалы живут в одной системе без переключения между программами.
4. **Детерминизм > ИИ** — всё, что можно сделать кодом, делается кодом. ИИ — только там, где без него принципиально нельзя (нормализация свободного текста, семантический матч после детерминированного поиска, предложение аналогов, извлечение данных из чертежей). Арифметика, валидация, поиск по каталогу, статусные машины, права доступа, сборка отчётов — это всегда детерминированная логика. ИИ-вызовы недетерминированы, платные, медленные и зависят от внешнего API — каждый лишний вызов подрывает принцип №2.

## Папка plans/

## Как работать с проектом

- Перед любой задачей — прочитай этот файл, затем нужные документы из .business/ и plans/.
- Если меняется бизнес-логика — обнови .business/INDEX.md и нужные файлы.
- Если меняется технический план — обнови соответствующий план в plans/.
- Если появляется новая важная папка или документ — обнови этот CLAUDE.md.

## ВАЖНО: план для каждой новой функции

Любая функция, которую мы создаём в любом чате, всегда оформляется планом в папке plans/.

Правила:

1. Один план = одна функция. Если план уже есть — работаем с ним.
2. Имя файла: YYYY-MM-DD-название-функции.md.
3. План делится на фазы. У каждой фазы статус `[ ]` или `[x]`.
4. В конце плана — итоговый блок: реализован целиком или нет, что осталось.
5. Любой агент обязан актуализировать план после каждой сессии.
6. **Каждая фаза закрывается прогоном `reviewer` (subagent в `.claude/agents/reviewer.md`).** Фаза помечается `[x]` только после того, как reviewer вернул отчёт и все блокирующие замечания закрыты. Отчёт reviewer'а кратко фиксируется в плане под фазой (что проверили, что исправили). Для ранее выполненных фаз, закрытых до введения этого правила, ретро-прогон reviewer обязателен перед стартом новых фаз того же плана.

## ВАЖНО: завершение каждого чата

В конце каждой сессии записывай рефлексию в файл .business/история/YYYY-MM-DD-краткое-название.md (создавай папку при необходимости).

Формат:

1. Какая задача была поставлена.
2. Как я её решал.
3. Решил ли — да / нет / частично.
4. Эффективно ли решение, что можно было лучше.
5. Как было и как стало.
